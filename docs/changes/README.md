# Change history

- Add one file per agent session at `docs/changes/YYYY/MM/DD-short-topic.md`. Add a short suffix if a name already exists.
- Use the session's local date. Keep each note under 20 lines and write short bullets.
- Start with a heading containing the date and topic, then an author bullet: agent name and requesting person when known.
- Add an `Instructions:` bullet for new guidance and where it was saved, or say there was no new lasting guidance.
- Add a `Changed:` bullet summarizing the result. Link to the affected module docs when useful.
- Add a `Checks:` bullet with commands or concrete verification and the result. State failures or skipped checks plainly.
- Add a `Next:` bullet only for unfinished work, known limits, or required follow-up.
- Update your own note as the session progresses, including across multiple pushes. Leave earlier sessions' notes intact; record corrections in a new note.
- Don't paste prompts, diffs, file lists, or credentials. Git already keeps exact changes.
- Current rules live in `AGENTS.md` and module docs; old notes are history, not extra instructions to load every time.
- To find history, search this folder by date, feature, or instruction. There is no ever-growing index to maintain.
