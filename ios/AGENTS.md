# Check Price iPhone app (`ios/`)

- This is the main iPhone app (owner decision, 2026-11-15). It started as a teammate's SwiftUI prototype: capture → analyzing → verdict reveal → report → watchlist, now wired to the Convex backend (see Backend below). No Shortcut, App Intents or push notifications yet; don't describe them as working.
- It supersedes `notyet/ios/`. Not Yet stays in the repo for reference until the owner decides what to do with it. Don't edit it for Check Price work.
- Direction: keep this app's screens, flow and content; give them Not Yet's look and interaction design (the Worldscape design language). No new features or screens unless the owner asks. More specific instructions are coming, so keep changes reversible.

## Design rules

- Read `notyet/ios/design/worldscape-language.md`, including the component catalog (section 5). Short version: dark only; only keys have depth; Hiragino Sans by role; springy arrival, quiet exit. Colours are no longer Worldscape's blues (owner, 2026-11-15): Anthropic-style warm neutrals, canvas `#141413`, text warm off-white `#FAF9F5` at fixed opacities, fills and strokes white at fixed opacities, flat canvas behind every screen (no top gradient), no blue anywhere. One accent, orange `Palette.accent` `#D97757`, only for the primary action, focus (carets) and selected states; links and quiet marks are neutral grey (`Palette.muted` `#B0AEA5`).
- Use the pieces in `CheckPrice/DesignSystem/` (copied from `notyet/ios/Views/DesignSystem/`): `Palette`, `TextStyle`/`.textStyle()`, `Spacing`, `Radius`, `ControlHeight`, `Shadows`, `Motion`, `.transition(.rise)`, `KeyButtonStyle`, `QuietButtonStyle`, `GlassSurface`/`.glassSurface()`, `GlassCardButtonStyle`, `FlatCard`, `Hairline`, `Chip`, `Bubble`, `OutlinedField`, `ScreenTitle`, `SectionLabel`, `ListRowButtonStyle`, `RoundIcon`, `IconPressStyle`, `HoppingDots`, `ThinkingLine`, `.shimmering()`, `StreamingText`, `WorkingIndicator`, `FailureNote`, `InputBarSurface`, `SampleDataTag`, `ConfidenceMeter`, `PriceChartView`.
- No screen titles (owner, 2026-11-15): no in-content heading that names the screen and no navigation-bar title. Back buttons and bar buttons stay. The Account top bar keeps the user's handle, as profile info. The Settings sheet shows "Settings" centred beside its X (owner, 2026-11-15). Threads' pushed Watchlist and Hearted screens show their name in the bar, since nothing else on them says which list it is (2026-11-15).
- Nothing beyond what the owner specified for a screen (owner, 2026-11-15): no explanatory text, disclaimers ("sample data", "prototype", "not connected yet"), helper or instruction lines, suggested prompts, captions, footnotes or decorative extras. Don't add new pieces.
- No section labels that only name the section (Summary, Verdicts, Price, Chat, Set up): spacing separates blocks. Empty states show nothing rather than a line of text.
- Show information plainly: a number or a word instead of a sentence ("Back Tap", not "Set Back Tap or Action Button"). When in doubt, remove.
- Font: Hiragino Sans only, through `TextStyle`/`.textStyle()` or `Font.hiragino`; never `.font(.system(...))`, `.headline` and the like, serif or rounded on text (SF Symbols may keep `.system` sizes). iOS ships only `HiraginoSans-W3`, `-W6`, `-W7`: `HiraginoWeight` w3/w4/w5 (regular, medium) → W3, w6 (semibold) → W6, w7 (bold, heavy) → W7, named directly with `Font.custom(_:size:relativeTo:)`.
- The tab bar is icons only, no names under them (owner, 2026-11-15): outline when not selected, filled when selected (`house`, `bubble.left.and.text.bubble.right`, `person.crop.circle`). Titles stay on the items, drawn clear, so VoiceOver reads them.
- Verdicts: `Verdict.word`, `.symbol`, `.color` (`DesignSystem/VerdictStyle.swift`): Buy green, Wait amber, Look around lavender, Check first coral.
- How Not Yet drew similar screens: `notyet/ios/Views/` (for example `ProductReportView.swift`, `HomeView.swift`, `HistoryView.swift`).

## Backend

- `ShopperKit/` is Ruhaan's Swift package from branch `ruhaan_ios`: contract models, HTTP client (one bounded retry), anonymous device id, on-device screenshot reading. The app uses it through `CheckPrice/Backend/`.
- Check price: a store link on the clipboard goes to `POST /analyze`; otherwise the user picks a screenshot, read on the phone (the image never leaves it). The verdict starts a thread; its report polls `GET /report` until the full analysis is in. Save calls `/watchlist/save` and `/remove`.
- Key: copy `Config/Secrets.example.xcconfig` to `Config/Secrets.xcconfig` (git-ignored) with the dev `APP_API_KEY`. Debug builds only; Release never carries it. Without a key, Check price runs the demo, as do `-autoReveal YES` and demo threads.
- ShopperKit tests with only Command Line Tools: `cd ios/ShopperKit && F=/Library/Developer/CommandLineTools/Library/Developer; DYLD_LIBRARY_PATH=$F/usr/lib swift test -Xswiftc -F$F/Frameworks -Xlinker -F$F/Frameworks -Xlinker -rpath -Xlinker $F/Frameworks -Xlinker -rpath -Xlinker $F/usr/lib`.

## Live Activity (Dynamic Island)

- Two stages: `checking` (warm grey wisps with an orange edge, a playful word that changes each update, e.g. "Bargainating", from `CheckingWords` in `Shared/CheckAttributes.swift`: random start, +1 per `phase`; no "…"; compact trailing capped at 100 pt, shrinks to 75%) and `decided` (the same wisps re-hued to the verdict, the verdict word, a reason of about 8 words at most). Words: Buy Now, Buy Later (yellow), Look Around, Check First. Never a "don't buy" (owner, 2026-11-15).
- Show nothing else: no store, product name, clock or other icon, no logo yet. The compact leading and minimal slots are empty (`EmptyView()`), kept for a future logo. Everything is centred, in Hiragino Sans, the Worldscape font: `HiraginoSans-W6` for the verdict word, `HiraginoSans-W3` for the reason. No serif, rounded or system fonts (owner, 2026-11-15).
- Colours: checking uses the input bar's warm greys (`InputBarSurface`: `#262523 → #2D2C29`, top `#0F0F0E`, bottom light `#6E6C66` then accent `#D97757`, fog `#FAF9F5`); each verdict has a hand-picked set in `Widget/WispField.swift`. The owner will tune these.
- Platform limits: the island's outer pill is always black, so the art sits inside it; no Metal, TimelineView or looping animation. Motion comes from bumping `phase` in each update (iOS animates up to about 2 s between states).

## Files

- `CheckPrice/ContentView.swift`: root tabs (Home, Threads, Account), the thread detail sheet (shown whenever `ThreadStore.openThreadID` is set, cleared on dismiss), launch arguments. Each tab sits on the flat canvas colour, so screens don't draw their own. `ThreadStore.shared` is also in the environment (`@Environment(ThreadStore.self)`).
- `CheckPrice/Components/TabBar.swift`: `AppTab` and `TabBarStyle`, the system tab bar dressed as Not Yet's dark glass (one row of three, no search tab, icons only), and `TabBarIconInsets`, which moves each icon down into the space the hidden title leaves.
- `CheckPrice/Screens/`: `Home/HomeView` (first screen `Home/PrimaryCheckArea`: capture, analyzing, reveal, swappable as one view; below it `Home/HomeSummary`: totals, verdicts, recent threads), `Threads/ThreadsView` (laid out like the Claude app's sidebar, owner 2026-11-15: Watchlist and Hearted nav rows, then Recents, every thread newest first as one line of product name with no tags; swipe or long-press to heart or save), `Threads/ThreadDetailView` (pushed or sheet: report from `ThreadDetailReport`, demo chart history from `ThreadDetailHistory`, chat from `ChatColumn` and `ChatInputBar`), `Account/AccountView` (its gear opens `Account/AccountSettingsView` as a sheet, laid out like the Claude app's Settings, owner 2026-11-15: X and centred title, account card, Account and App cards; a chevron only on rows that open something).
- `CheckPrice/Components/`: `Card` (a padded `FlatCard`), `Metric` (label over value), `SignalRow` (product row on a flat card, optional trailing note), restyled in Worldscape. `Badge` is retired.
- `CheckPrice/Models/Demo.swift`: `Verdict`, `Product`, `Demo` data.
- `CheckPrice/LiveActivity/CheckActivity.swift` starts and updates the pop-up (also from Home's reveal); `Shared/CheckAttributes.swift` (app and widget) holds its state; `Widget/` is the widget extension `CheckPriceWidgets` with the views and wisp art.
- When agents work in parallel, each owns its screen files. `Components/`, `DesignSystem/` and `Models/` are shared: add new pieces freely, but change or remove an existing one only by agreement, since other screens use it.

## Build and run

- `cd ios && xcodegen generate` (XcodeGen from Homebrew). The generated `CheckPrice.xcodeproj` is not committed.
- Simulator build: `xcodebuild -project CheckPrice.xcodeproj -scheme CheckPrice -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath build build`. The app lands in `build/Build/Products/Debug-iphonesimulator/Check Price.app`. iOS 18+, unsigned.
- Launch arguments (`xcrun simctl launch booted com.ycconsumerhackathon.checkprice <args>`): `-startTab home|threads|account`, `-autoReveal YES` (runs the capture → reveal demo on launch; screenshot within 3.5s for analyzing, after for the reveal), `-openThread YES` (opens the newest thread's detail sheet), `-demoLiveActivity YES` with optional `-demoVerdict wait|buy|alternative|investigate` (default wait: checking words for 6 s with the wisps moving every 1.5 s, then the verdict with an alert). iOS hides an app's own Dynamic Island while the app is open, so swipe home right after launch. `-autoReveal YES` also plays the pop-up over 3.5 s.
- Without full Xcode, run `scripts/typecheck.sh`: it type-checks the app and the widget extension as Mac Catalyst iOS 18. ActivityKit and WidgetKit are marked unavailable on Catalyst, so it builds stand-ins from the macOS SDK's interface files with those bans removed. This is not an iOS build.
