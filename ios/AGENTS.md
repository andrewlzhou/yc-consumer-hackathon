# Check Price iPhone app (`ios/`)

- This is the main iPhone app (owner decision, 2026-11-15). It started as a teammate's SwiftUI prototype: capture → analyzing → verdict reveal → report → watchlist, now wired to the Convex backend (see Backend below). Shortcut actions exist (see Back Tap result below) but are not yet proven on a real iPhone; no push notifications yet. Don't describe unproven parts as working.
- It supersedes `notyet/ios/`. Not Yet stays in the repo for reference until the owner decides what to do with it. Don't edit it for Check Price work.
- Direction: keep this app's screens, flow and content; give them Not Yet's look and interaction design (the Worldscape design language). No new features or screens unless the owner asks. More specific instructions are coming, so keep changes reversible.

## Design rules

- Read `notyet/ios/design/worldscape-language.md`, including the component catalog (section 5). Short version: dark only; only keys have depth; Hiragino Sans by role; springy arrival, quiet exit. Colours are no longer Worldscape's blues (owner, 2026-11-15): Anthropic-style warm neutrals, canvas `#141413`, text warm off-white `#FAF9F5` at fixed opacities, fills and strokes white at fixed opacities, no blue anywhere. Every screen, tab, pushed page and sheet sits on one backdrop (owner, 2026-11-15): `AppBackdrop` (`DesignSystem/Backdrop.swift`), a still frame of the old Home aurora (warm light low on the canvas, top darkened, no animation), drawn by ContentView behind tabs and by each pushed or presented screen; light at 70% so secondary text on cards keeps 4.5:1. One accent, orange `Palette.accent` `#D97757`, only for the primary action, focus (carets) and selected states; links and quiet marks are neutral grey (`Palette.muted` `#B0AEA5`).
- Use the pieces in `CheckPrice/DesignSystem/` (copied from `notyet/ios/Views/DesignSystem/`): `Palette`, `TextStyle`/`.textStyle()`, `Spacing`, `Radius`, `ControlHeight`, `Shadows`, `Motion`, `.transition(.rise)`, `KeyButtonStyle`, `QuietButtonStyle`, `GlassSurface`/`.glassSurface()`, `GlassCardButtonStyle`, `FlatCard`, `Hairline`, `Chip`, `Bubble`, `OutlinedField`, `ScreenTitle`, `SectionLabel`, `ListRowButtonStyle`, `RoundIcon`, `IconPressStyle`, `HoppingDots`, `ThinkingLine`, `.shimmering()`, `StreamingText`, `WorkingIndicator`, `FailureNote`, `InputBarSurface`, `SampleDataTag`, `ConfidenceMeter`, `PriceChartView`, `AppBackdrop`.
- No screen titles (owner, 2026-11-15), except where the owner asked for one: no in-content heading that names the screen and no navigation-bar title. Back buttons and bar buttons stay. Titled screens (owner, 2026-11-15): Library (the Threads tab, "Library" large and left in the content) and Settings (the Account tab, "Settings" small, bold and centred in the bar).
- Nothing beyond what the owner specified for a screen (owner, 2026-11-15): no explanatory text, disclaimers ("sample data", "prototype", "not connected yet"), helper or instruction lines, suggested prompts, captions, footnotes or decorative extras. Don't add new pieces.
- No section labels that only name the section (Summary, Verdicts, Price, Chat, Set up): spacing separates blocks. Empty states show nothing rather than a line of text.
- Show information plainly: a number or a word instead of a sentence ("Back Tap", not "Set Back Tap or Action Button"). When in doubt, remove.
- Font: Hiragino Sans only, through `TextStyle`/`.textStyle()` or `Font.hiragino`; never `.font(.system(...))`, `.headline` and the like, serif or rounded on text (SF Symbols may keep `.system` sizes). iOS ships only `HiraginoSans-W3`, `-W6`, `-W7`: `HiraginoWeight` w3/w4/w5 (regular, medium) → W3, w6 (semibold) → W6, w7 (bold, heavy) → W7, named directly with `Font.custom(_:size:relativeTo:)`.
- The tab bar is icons only, no names under them (owner, 2026-11-15): outline when not selected, filled when selected (`house`, `bubble.left.and.text.bubble.right`, `person.crop.circle`). VoiceOver still reads the names: before iOS 26 the titles stay on the items, drawn clear; iOS 26 ignores that colour, so there the labels are the image alone and `TabBarItemHook` sets each item's accessibility label.
- Verdicts: `Verdict.word`, `.symbol`, `.color` (`DesignSystem/VerdictStyle.swift`): Buy green, Wait amber, Look around lavender, Check first sand (was coral; changed 2026-11-15 so it isn't confused with the orange accent). Library rows show the verdict as a small round badge on the picture's bottom-right corner.
- How Not Yet drew similar screens: `notyet/ios/Views/` (for example `ProductReportView.swift`, `HomeView.swift`, `HistoryView.swift`).

## Backend

- `ShopperKit/` is Ruhaan's Swift package from branch `ruhaan_ios`: contract models, HTTP client (one bounded retry), anonymous device id, on-device screenshot reading. The app uses it through `CheckPrice/Backend/`.
- Check price: a store link on the clipboard goes to `POST /analyze`; otherwise the user picks a screenshot, read on the phone (the image never leaves it). The verdict starts a thread; its report polls `GET /report` until the full analysis is in. Save calls `/watchlist/save` and `/remove`.
- Key: copy `Config/Secrets.example.xcconfig` to `Config/Secrets.xcconfig` (git-ignored) with the dev `APP_API_KEY`. Debug builds only; Release never carries it. Nothing inside the app starts a check (Home's "plus" button and its check sheet were removed, owner 2026-11-15): checks come from the Shortcut actions below, through `CheckRunner` in `Backend/Backend.swift` (link or screenshot → verdict). Without a key they show the failure. Never put a real key in a cloud build: `ios/.capyignore` keeps the file out of uploads.
- ShopperKit tests with only Command Line Tools: `cd ios/ShopperKit && F=/Library/Developer/CommandLineTools/Library/Developer; DYLD_LIBRARY_PATH=$F/usr/lib swift test -Xswiftc -F$F/Frameworks -Xlinker -F$F/Frameworks -Xlinker -rpath -Xlinker $F/Frameworks -Xlinker -rpath -Xlinker $F/usr/lib`.

## Back Tap result (App Intents, iOS 26+)

- Shortcut actions in `CheckPrice/Intents/`: Check Price in Screenshot (Back Tap: Take Screenshot, then this) and Check Price of Link. They run in the background and return a compact snippet (`CompactVerdictView`).
- The popup is decision only (Ruhaan, 2026-11-15): the verdict colour, one word, and a blue button titled exactly **More Details**. No reason, title, confidence or timings. "Sample data" shows only when the evidence is seeded. Words, one per backend verdict (`Verdict.compactLabel`): BUY, WAIT, LOOK ELSEWHERE, INDETERMINATE. The island keeps its own words.
- A tap anywhere on the result runs `OpenProductIntent` (foreground): `ThreadStore.openProduct` opens the newest check of that `productId`. `checkprice://product/<productId>` does the same; links carry only the opaque id. A product never checked on this phone opens nothing.
- iOS draws the platter and its Done button; an app can't rename, restyle or remove them.
- A failed check or a build with no key shows the failure, never a demo verdict.
- The detail page of a real check shows only real facts: "Why" is the report's reasoning when its analysis was made for this check's price, else the check's own reason; "Prediction" appears only with a price, a chart or a report still loading; "Sources" lists the report chart's sources. Demo history, pictures and sources go only to demo products (`Product.check == nil`).
- Real checks are kept in `checks.json` (`Models/ScanArchive.swift`), since iOS may close the app between the check and the tap. Demo threads are never saved.
- A check keeps its own price, store, verdict and reason (`CheckSnapshot`). `GET /report` is about the product (its newest analysis may be another scan's), so it adds history, and its verdict, reason and forecast only when made for the same price (`Backend/ReportFigures.swift`). A link gets today's price only from its own store, seen in the last 7 days.
- Screenshot: read in memory; the file is deleted only inside this app's temp or cache folder or Shortcuts' `/var/mobile/tmp`, never Documents, Files, iCloud Drive or Photos. Debug builds record each run's facts (`ScanDiagnostics`: sizes, file kind, deleted, seconds; no screen text or paths).

## Live Activity (Dynamic Island)

- Two stages: `checking` (warm grey wisps with an orange edge, a playful word that changes each update, e.g. "Bargainating", from `CheckingWords` in `Shared/CheckAttributes.swift`: random start, +1 per `phase`; no "…"; compact trailing capped at 100 pt, shrinks to 75%) and `decided` (the same wisps re-hued to the verdict, the verdict word, a reason of about 8 words at most). Words: Buy Now, Buy Later (yellow), Look Around, Check First. Never a "don't buy" (owner, 2026-11-15).
- Show nothing else: no store, product name, clock or other icon, no logo yet. The compact leading and minimal slots are empty (`EmptyView()`), kept for a future logo. Everything is centred, in Hiragino Sans, the Worldscape font: `HiraginoSans-W6` for the verdict word, `HiraginoSans-W3` for the reason. No serif, rounded or system fonts (owner, 2026-11-15).
- Colours: checking uses the input bar's warm greys (`InputBarSurface`: `#262523 → #2D2C29`, top `#0F0F0E`, bottom light `#6E6C66` then accent `#D97757`, fog `#FAF9F5`); each verdict has a hand-picked set in `Widget/WispField.swift`. The owner will tune these.
- Platform limits: the island's outer pill is always black, so the art sits inside it; no Metal, TimelineView or looping animation. Motion comes from bumping `phase` in each update (iOS animates up to about 2 s between states).

## Build and run

- `cd ios && xcodegen generate` (XcodeGen from Homebrew). The generated `CheckPrice.xcodeproj` is not committed.
- Simulator build: `xcodebuild -project CheckPrice.xcodeproj -scheme CheckPrice -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath build build`. The app lands in `build/Build/Products/Debug-iphonesimulator/Check Price.app`. iOS 18+, unsigned.
- Launch arguments (`xcrun simctl launch booted com.ycconsumerhackathon.checkprice <args>`): `-startTab home|threads|account`, `-openThread YES` (opens the newest thread's detail sheet), `-demoLiveActivity YES` with optional `-demoVerdict wait|buy|alternative|investigate` (default wait: checking words for 6 s with the wisps moving every 1.5 s, then the verdict with an alert). iOS hides an app's own Dynamic Island while the app is open, so swipe home right after launch.
- Tests: `xcodebuild test -project CheckPrice.xcodeproj -scheme CheckPrice -destination 'platform=iOS Simulator,name=iPhone 16,OS=26.5' CODE_SIGNING_ALLOWED=NO` (or the same on Revyl's runner). `xcrun simctl openurl booted checkprice://product/<productId>` opens a real product's thread.
- Without full Xcode, run `scripts/typecheck.sh`: it type-checks the app and the widget extension as Mac Catalyst iOS 18. ActivityKit and WidgetKit are marked unavailable on Catalyst, so it builds stand-ins from the macOS SDK's interface files with those bans removed. This is not an iOS build.
